   - Props: `onNext: () => void`
   - Heading: "Welcome to EssayGrader!" (per locked decision)

   - Single CTA button: "Let's Go" — calls `onNext`.

   - Props: `onNext: () => void`, `onSkip: () => void`
   - Heading: "What's your primary writing purpose?"
   - Three SelectableCard options in a row: Work (Briefcase icon), School (GraduationCap icon), Other (Sparkles icon)
   - On selection: call `updateProfile({ writingPurpose: selected })` from `@/api/auth`, then call `useProfileStore.getState().setWritingPurpose(selected)`, then `onNext()`. Await the PATCH before advancing. Show loading state on the selected card or a brief spinner if needed.
   - Skip button: styled as text/ghost variant below the cards ("Skip for now"). Calls `onSkip` which advances without PATCH.
   - If PATCH fails, show toast via sonner but still allow proceeding (per research anti-pattern guidance).

5. **GradeLevelStep.tsx**: Grade level selection (REQUIRED — cannot skip).
   - Props: `onNext: () => void`, `onBack: () => void`
   - Heading: "What grade level do you teach or study?"
   - Four SelectableCard options in a 2x2 grid: Elementary (BookOpen icon), Middle School (School icon), High School (Building2 icon), College (GraduationCap icon)
   - Use the values from `GradeLevel` type: "elementary", "middle-school", "high-school", "college" with labels from `GRADE_LEVEL_LABELS`.
   - "Next" button is DISABLED until a card is selected. On click: call `updateProfile({ gradeLevel: selected })`, then `useProfileStore.getState().setGradeLevel(selected)`, then `onNext()`. Await PATCH before advancing.
   - "Back" button (text/ghost variant or outlined) calls `onBack`.
   - If PATCH fails, show toast but still advance (preference can be set later from profile).

6. **CompletionStep.tsx**: Completion confirmation with redirect.
   - Props: none (handles its own redirect)
   - "You're all set!" heading.
   - Checkmark animation: motion.div with `initial={{ scale: 0 }} animate={{ scale: 1 }}` spring transition wrapping a Check icon (lucide) in a `bg-primary rounded-full` circle (`h-20 w-20`).
   - `useEffect` with `setTimeout` of 1500ms that calls `useNavigate()` to navigate to `/grade`. Clean up timeout on unmount.

7. **RegistrationWizard.tsx**: Step orchestrator.
   - Props: none (self-contained, uses store)
   - State: `step` (0-3 for Welcome, WritingPurpose, GradeLevel, Completion), `direction` (1 or -1 for animation direction)
   - `goNext`: setDirection(1), setStep(s+1)
   - `goBack`: setDirection(-1), setStep(s-1)
   - Renders inside a wide centered card container: `max-w-3xl w-[75vw] mx-auto` with padding. On smaller screens, allow full width.
   - WizardProgress at top (totalSteps=4, currentStep=step)
   - AnimatePresence with `mode="wait"` and `custom={direction}`. Each step wrapped in `motion.div` with `custom={direction}`, `variants` for enter/center/exit (x: 300/-300 based on direction), `transition={{ duration: 0.3, ease: "easeInOut" }}`. Use `key={step}` for AnimatePresence.
   - CRITICAL: Set `custom={direction}` on BOTH AnimatePresence and motion.div (per pitfall #1 in research).
   - Step 0: WelcomeStep, Step 1: WritingPurposeStep, Step 2: GradeLevelStep, Step 3: CompletionStep.
   - WritingPurposeStep receives `onSkip` that calls `goNext` (skips without saving).

1. **RegisterPage.tsx** — Complete rewrite of the placeholder. Three-phase page:

   Phase A (Registration Form): Shown when user is NOT signed in.
   - Wide centered card layout matching wizard width (`max-w-3xl w-[75vw] mx-auto`, consistent with wizard container)
   - Heading: "Create your account"
   - Email input, Password input (minLength 8), Confirm Password input
   - "Create Account" submit button with loading state (Loader2 spinner, same pattern as SignInDialog)
   - Error display for validation/API errors (`text-sm text-destructive`)
   - "Already have an account? Sign in" link at bottom — links to `/` (landing page where sign-in is accessible)
   - On successful registration: calls `useProfileStore.getState().register(email, password)`. On success, the store sets isSignedIn=true and gradeLevel=null. The component state transitions to Phase B (wizard).

   Phase B (Wizard): Shown when user IS signed in AND gradeLevel is null.
   - Renders `<RegistrationWizard />` component
   - This handles both: (a) new registration flowing into wizard, and (b) returning user redirected here by ProtectedRoute wizard gate

   Phase C (Redirect): If user is signed in AND gradeLevel is NOT null, redirect to `/grade` via `<Navigate to="/grade" replace />`. This prevents already-onboarded users from seeing the registration page.

   Use `useProfileStore` selectors for `isSignedIn` and `gradeLevel` to determine which phase to show.

2. **ProtectedRoute.tsx** — Add wizard gate:
   - After the existing `isSignedIn` check, add a `gradeLevel` check:
   ```tsx
   const gradeLevel = useProfileStore((s) => s.gradeLevel);
   if (isSignedIn && gradeLevel === null) {
     return <Navigate to="/register" replace />;
   }
   ```
   - This forces authenticated users who haven't completed onboarding to the wizard.
   - Keep the existing unauthenticated redirect to `/` intact.
