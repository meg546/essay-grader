2. Create `src/components/layout/LandingLayout.tsx`:
   - Minimal layout: sticky header with logo (GraduationCapIcon + "EssayGrader" NavLink to "/") and a Sign In button (Button variant="outline" size="sm")
   - The Sign In button should NOT open a dialog itself -- it should scroll to or dispatch to the landing page. Simplest approach: use an `id="landing-sign-in-btn"` on the button and let the LandingPage component attach a click handler via ref or event. OR even simpler: don't put Sign In in the header layout at all -- the hero CTA handles sign in. BUT the locked decision says "Landing page shows minimal header: logo + Sign In button only." So: the LandingLayout should accept an `onSignInClick` callback prop -- BUT it uses Outlet so can't pass props. Instead: use a simple approach -- the LandingLayout renders the header with a Sign In button that dispatches a custom event `window.dispatchEvent(new Event('landing-sign-in'))`, and the LandingPage listens for it. OR even simpler: just make LandingLayout render the header and Outlet, and pass the Sign In click via a React context. SIMPLEST: Make the header Sign In button part of the LandingPage component itself (fixed/sticky), not in a separate layout. Actually, the cleanest approach per the research: LandingLayout renders the header with the button, and uses a zustand-style tiny store or just a DOM click approach.

   FINAL APPROACH: Create LandingLayout as a component that renders the minimal header + Outlet. For the Sign In button in the header, use `document.dispatchEvent(new CustomEvent('open-sign-in'))` on click. The LandingPage component listens for this event with useEffect to open the SignInDialog. This avoids prop drilling through Outlet.

   - Header styling should match existing Header.tsx: `sticky top-0 z-40 border-b border-border bg-card/80 backdrop-blur-sm`, `flex h-14 items-center justify-between px-4`
   - Use existing Tailwind theme tokens only -- supports dark mode automatically
