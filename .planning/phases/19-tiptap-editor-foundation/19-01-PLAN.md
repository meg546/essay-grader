   After install, verify single @tiptap/core version: `npm ls @tiptap/core`

2. Rewrite `src/components/grading/EssayInput.tsx` to use Tiptap instead of the shadcn Textarea. The component must:

   a. **Keep the same exports**: `EssayInputHandle` interface (with `triggerFileUpload`), `EssayInput` component (forwardRef). Keep `EssayInputProps` with `disabled?: boolean` and `onFocus?: () => void`.

   b. **Editor setup via `useEditor`**:
      - `immediatelyRender: false` (locked decision from STATE.md)
      - StarterKit with ALL marks disabled: `bold: false, italic: false, strike: false, code: false, codeBlock: false, blockquote: false, heading: false, horizontalRule: false, bulletList: false, orderedList: false`
      - CharacterCount extension (imported from `@tiptap/extension-character-count`)
      - `content`: Read `useAppStore.getState().essayText` ONCE at mount. Convert to HTML: wrap in `<p>` tags, replace `\n\n` with `</p><p>`, replace remaining `\n` with `<br>`. If empty string, use `''`.
      - `onUpdate({ editor })`: Call `useAppStore.getState().setEssayText(editor.getText({ blockSeparator: '\n\n' }))` -- use `getState()` to avoid stale closure (Pitfall 3 from research).
      - `editorProps.attributes.class`: Use `cn()` to combine base classes `'outline-none flex-1 overflow-y-auto p-4 leading-relaxed min-h-[250px] md:min-h-[200px]'` with `TEXT_SIZE_CLASS[textSize]`. The `textSize` value comes from `useAppStore((s) => s.textSize)` -- this is reactive so the class updates when text size changes.
      - `editorProps.attributes['aria-label']`: `'Essay text'`
      - `editable`: Set to `!disabled` so the editor respects the disabled prop.

   c. **Placeholder**: Tiptap has built-in placeholder support but it requires another extension. Instead, use CSS: when the editor is empty, ProseMirror adds `is-empty` class to the first paragraph. Add a CSS `::before` pseudo-element via Tailwind's `[&_.is-empty:first-child::before]` utility on the EditorContent wrapper, or add a `<style>` block. The placeholder text should be "Paste your essay here or drag and drop a file...". Alternatively, just skip placeholder for now -- Phase 20+ will add more toolbar chrome. Executor's choice on approach.

   d. **File drag-and-drop**: Keep the existing drag handler pattern. Wrap `EditorContent` in a `<div>` that has `onDragEnter`, `onDragLeave`, `onDragOver`, `onDrop` handlers. These handlers are identical to the current ones. When a file is dropped, call `handleFile(file)` which reads the file and calls `setEssayText(text)`. IMPORTANT: When file text is loaded via `setEssayText`, the store updates but the editor does NOT automatically reflect it (one-way sync). After `setEssayText(text)`, also call `editor?.commands.setContent(text ? ...)` to load the text into the editor. This is the ONE exception to "never setContent after mount" -- it is an explicit user action (file load), not a reactive sync loop. Use `editor?.commands.clearContent()` first if needed.

   e. **Hidden file input**: Keep the `<input type="file" ref={fileInputRef}>` and `handleFileInputChange` exactly as-is.

   f. **useImperativeHandle**: Keep the existing pattern exposing `triggerFileUpload`.

   g. **onFocus prop**: Wire `onFocus` by passing it through `editorProps.handleFocus` or by attaching an `onFocus` handler to the wrapper div. If using `editorProps`, the Tiptap onFocus event works: add `onFocus({ event }) { onFocus?.() }` to the useEditor config.

   h. **Remove**: The `<Textarea>` import and the `onChange` handler. Remove the import of `Textarea` from `@/components/ui/textarea`.

3. Verify `npm run build` succeeds with no TypeScript errors.
